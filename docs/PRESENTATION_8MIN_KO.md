# 자율 탐색·목표물 방문·복귀 시스템 — 8분 발표 대본

작성일: 2026-09-30

진행 안내: 구간별 시간은 목표 시간입니다. 화면 전환과 지도·카메라를 짚는 시간을 포함하여 약 8분으로 구성했습니다. 리허설에서 말하는 속도에 맞춰 조절하세요. 괄호 안 화면 안내는 읽지 않습니다.

## 0:00~0:45 — 프로젝트 목표

안녕하세요. 이번 프로젝트에서는 Webots의 아파트 환경에서 로봇이 지정된 색상의 목표물을 찾고, 목표물을 모두 방문한 뒤 시작 지점으로 돌아오는 자율 탐색 시스템을 구현했습니다.

이 과제는 단순히 로봇을 움직이거나 카메라로 사과를 인식하는 것만으로 해결되지 않습니다. 로봇은 처음 보는 환경에서 주변 구조를 파악해야 하고, 자신의 위치를 추정해야 하며, 가구와 사람을 피하면서 목표물까지 이동해야 합니다.

그래서 저희는 전체 시스템을 인식, 지도 작성, 위치 추정, 경로 계획, 그리고 임무 상태 관리로 나누었습니다. 오늘은 각 기능을 무엇으로 구현했는지, 왜 그 방식을 선택했는지, 실제 실행에서 어떤 문제가 발생했고 어떻게 개선하고 있는지를 설명하겠습니다.

## 0:45~1:30 — 전체 동작 구조

(화면 안내: Webots의 로봇과 실시간 지도 화면을 함께 보여줍니다.)

먼저 전체 동작 흐름입니다. 로봇은 카메라와 LiDAR로 주변을 관측하고, 바퀴 인코더와 컴퍼스로 이동량과 방향을 추정합니다. 이 정보를 바탕으로 지도를 갱신하고 다음 목적지를 선택한 뒤, 바퀴의 속도 명령을 계산합니다.

각 센서는 서로 다른 역할을 맡습니다. 카메라는 물체의 색상과 종류를 확인하고, LiDAR는 주변 장애물까지의 거리를 측정합니다. 인코더는 바퀴가 얼마나 회전했는지 알려주고, 컴퍼스는 로봇의 방향을 추정하는 데 사용합니다.

또한 모든 작업을 같은 주기로 실행하지 않았습니다. 충돌과 직접 관련된 센서 확인은 제어 주기에 맞춰 수행하고, YOLO 추론이나 지도 이미지 저장은 별도의 주기로 실행합니다. 이렇게 역할과 실행 주기를 나누어, 무거운 작업 때문에 주행 제어가 지연되는 것을 줄였습니다.

## 1:30~2:35 — 색상 탐지와 YOLO를 함께 쓰는 이유

(화면 안내: 카메라 영상의 노란 후보 표시와 초록 YOLO 박스를 가리킵니다.)

목표물 탐지에서는 HSV 색상 정보와 YOLO를 함께 사용했습니다.

우선 HSV를 이용해 지정된 색상의 영역을 찾습니다. HSV는 색상과 밝기를 분리해서 표현하기 때문에, 빨간색과 같은 색상 조건을 설정하기 편리합니다. 하지만 빨간색이라는 이유만으로 사과라고 판단할 수는 없습니다. 소화기, 가구, 벽의 글자도 비슷한 색을 가질 수 있기 때문입니다.

그래서 색상 후보의 크기, 형태, 채움비와 화면 위치를 확인하고, YOLO 결과를 추가로 활용합니다. 현재 YOLO는 주변 물체를 탐지하면서, 사과 후보와 겹치는 병처럼 명확한 다른 물체를 제외하는 보조 검증 역할도 수행합니다.

이렇게 구성한 이유는 기본 YOLO 모델이 시뮬레이션의 사과를 항상 사과로 분류하지는 않기 때문입니다. 실제로 단순한 형태의 사과를 스포츠 공으로 분류하는 사례도 확인했습니다. 따라서 YOLO의 클래스 이름 하나만으로 최종 판단하지 않고 여러 조건을 결합했습니다.

또한 큰 빨간 물체가 작은 사과 후보를 가리는 문제를 줄이기 위해 서로 떨어진 색상 영역을 각각 검사하도록 수정했습니다. 사과 뒤에 있는 큰 소파의 탐지 박스가 겹쳤다는 이유만으로 작은 사과 후보까지 제외하지 않도록, 박스의 상대적인 크기도 확인합니다.

## 2:35~3:25 — 지도와 목표물 표시의 의미

(화면 안내: 지도에서 빈 공간, 장애물, 미탐색 영역과 목표 표시를 가리킵니다.)

지도는 LiDAR 거리 측정을 작은 격자에 누적하는 방식으로 작성합니다. 각 격자에는 빈 공간인지, 장애물인지에 대한 관측을 쌓고, 아직 충분히 관측하지 못한 공간은 미탐색 영역으로 남겨둡니다.

목표물의 위치는 카메라에서 보이는 방향과 크기 등을 이용해 추정합니다. 따라서 로봇이 직접 도착하지 않은 곳에도 목표물의 추정 위치가 표시될 수 있습니다. 이것은 해당 장소를 이미 방문했다는 뜻이 아니라, 그 방향에 목표물이 있을 것으로 예상한다는 뜻입니다.

이 차이를 명확하게 보여주기 위해 미방문 목표물의 추정 위치는 노란색으로, 방문을 완료한 목표물은 빨간색으로 표시했습니다.

여기서 중요한 점은 지도상으로 확인된 공간과 카메라로 목표물까지 확인한 공간이 같지 않다는 것입니다. LiDAR는 주변을 360도로 보지만 카메라는 전방 약 60도만 보기 때문에, 길을 지나갔다는 사실만으로 그 주변의 사과를 모두 확인했다고 볼 수는 없습니다.

## 3:25~4:20 — 자기 위치 추정과 오차 보정

이 지도를 올바르게 작성하려면 로봇 자신의 위치도 알아야 합니다.

기본 위치 추정은 바퀴 인코더와 컴퍼스를 결합했습니다. 인코더에서 이동 거리를 계산하고, 컴퍼스에서 방향을 얻어 시작 위치를 기준으로 현재 좌표를 갱신합니다.

하지만 실제 실행에서는 가구에 걸렸을 때 문제가 발생했습니다. 로봇의 몸체는 거의 이동하지 않았는데 바퀴만 회전하면, 인코더는 로봇이 앞으로 움직였다고 계산합니다. 이런 오차가 누적되면 지도상의 위치와 실제 위치가 벌어지고, 복귀 경로도 잘못 계산할 수 있습니다.

이를 보완하기 위해 현재 LiDAR 관측을 기존 지도와 비교하는 국소 지도 정합 기능을 추가했습니다. 추정 위치 주변에서 장애물 관측이 더 잘 맞는 위치를 찾고, 충분한 일치가 확인될 때만 위치를 보정합니다. 관측이 부족하거나 잘 맞지 않는 경우에는 보정을 적용하지 않습니다.

다만 현재는 국소적인 위치 보정 단계입니다. 과거 장소를 다시 인식해 지도 전체의 누적 오차를 수정하는 전역 루프 폐합까지 구현한 상태는 아닙니다.

## 4:20~5:20 — 탐색 경로와 가구 주변 회피

탐색 목적지는 이미 확인한 빈 공간과 아직 모르는 공간의 경계에서 선택합니다. 새로운 정보를 얻을 수 있는 곳을 우선하고, 목적지까지의 경로는 A* 알고리즘으로 계산합니다. 주행 중에는 현재 LiDAR 관측에 따라 속도와 방향을 보정합니다.

이때 이미 지나간 길을 무조건 금지하지는 않습니다. 새로운 방으로 이동하거나 시작점으로 복귀하려면 기존 통로를 다시 이용해야 할 수 있기 때문입니다. 대신 도달했던 탐색 지점을 계속 새 목적지로 선택하거나, 접근에 진전이 없는 목적지를 계속 따라가는 경우를 줄이도록 했습니다.

가구 주변에서는 전진과 후진, 좌우 회전이 반복되는 문제도 발견했습니다. 가까운 가구 다리가 좌우로 번갈아 측정될 때 회피 방향이 매번 바뀌는 경우와, 가구를 동적 장애물로 잘못 판단한 정보가 계속 남는 경우가 있었습니다.

이를 개선하기 위해 정지한 가구로 판정한 관측은 정적 지도에 반영하도록 수정했습니다. 가까운 가구를 피할 때에는 회전 방향을 유지하고, 짧게 후퇴한 뒤 충분한 공간이 확보될 때까지 정지 회전하도록 했습니다. 안전거리를 무조건 줄이는 것보다 회피 판단의 일관성을 높이는 데 중점을 두었습니다.

## 5:20~6:10 — 임무 관리와 시작점 복귀

전체 임무는 상태 머신으로 관리합니다. 주변 확인, 탐색, 목표물 접근, 시작점 복귀, 갇힘 복구, 완료처럼 동작을 상태로 나누고, 센서 관측과 진행 상황에 따라 상태를 전환합니다.

예를 들어 탐색 중 목표물이 확인되면 접근 상태로 이동합니다. 필요한 목표물을 모두 방문하면 복귀 상태로 바뀌고, 시작 위치까지의 경로를 계산합니다. 지도 기반 경로를 찾기 어려우면 이동하면서 기록한 경유점을 이용하는 방식도 준비했습니다.

복귀 중 장애물에 걸려 복구 동작을 수행하더라도, 복구가 끝난 뒤에는 다시 시작점을 향하도록 목적을 유지합니다. 시작점에 도착해 완료 상태가 되면 바퀴의 이동 속도와 회전 속도를 즉시 0으로 만듭니다.

성공 판정도 시작점 도착 여부만으로 결정하지 않습니다. 필요한 목표물을 모두 방문했는지 함께 확인합니다. 목표물을 찾지 못한 상태로 돌아온 경우는 임무 성공으로 기록하지 않도록 구분했습니다.

## 6:10~7:00 — GPU와 실시간 모니터링

성능 측면에서는 Webots의 3D 렌더링과 YOLO 추론에 GPU를 사용하도록 구성했습니다. YOLO는 CUDA 장치에서 동작하며, 기본 추론 주기는 시뮬레이션 시간 기준 약 0.25초입니다. 동일한 영상의 추론 결과는 재사용합니다.

하지만 GPU를 사용한다고 전체 시뮬레이션이 같은 비율로 빨라지지는 않습니다. 물리 연산과 영상 전처리, 지도 갱신, 경로 계획, 이미지 저장도 실행 시간에 영향을 줍니다. 그래서 처리 단계별 시간을 측정하고, 색상 변환을 OpenCV로 처리하며 화면 저장 주기를 제한했습니다.

실시간 화면에는 지도와 카메라 영상뿐 아니라 임무 상태, 목표물 방문 수, 추정 위치, GPU 사용 정보와 실행 배속을 표시합니다. 최근에는 탐지 후보가 탈락한 이유와 장애물 회피 상태도 추가했습니다.

이 정보는 로봇이 멈추거나 사과를 지나쳤을 때, 단순히 동작만 보는 것이 아니라 어느 판단 단계에서 문제가 생겼는지 확인하기 위한 것입니다.

## 7:00~8:00 — 검증 결과와 한계

마지막으로 검증 결과입니다.

현재 기존 단위 테스트 15개와 추가 회귀 테스트 50개가 통과했습니다. 회귀 테스트에는 큰 빨간 배경 옆의 작은 사과를 검사하는 경우, 배경 가구의 박스와 겹치는 경우, 같은 탐색 지점을 반복 선택하는 경우, 회피 방향이 반전되는 경우와 복귀 상태 전환 등이 포함됩니다.

실제 GPU에서도 추론이 실행되는지, 같은 영상의 결과가 재사용되는지 확인했습니다. 사람 없는 가구 배치의 중간 수정본 시뮬레이션에서는 목표물 방문 후 시작점 약 24센티미터 이내로 충돌 없이 복귀했습니다.

다만 이 결과를 모든 상황에서의 성공으로 해석할 수는 없습니다. 중간 수정 과정에서는 좁은 가구 환경에서 충돌이나 통로 통과 실패가 발생했습니다. 이를 수정한 최신 오프라인 테스트에서는 사람 유무 두 경우 모두 목표 방문과 무충돌 복귀를 통과했습니다. 실제 아파트에서도 재방문 정책을 적용한 검증 실행 한 번은 목표물 두 개를 모두 방문하고 시작점 약 13.5센티미터 이내로 복귀했습니다. 이후 추가한 통로 수정까지 포함한 실제 완주와 여러 조건에서의 재현성은 더 확인해야 합니다.

앞으로는 카메라에서 보이는 목표물을 놓치는 조건을 기록해 줄이고, 좁은 공간에서 충돌 방지와 이동 가능성을 함께 만족하도록 회피 로직을 개선하겠습니다. 이번 프로젝트를 통해 인식, 위치 추정, 지도와 제어를 연결하는 것뿐 아니라 실제 실행 결과로 각 판단을 검증하는 과정이 중요하다는 것을 확인했습니다. 감사합니다.

## 발표자 검증 메모 — 낭독 제외

- 최신 검증 수는 `python run_tests.py` 15/15 및 `python -m unittest discover -s tests -q` 50/50입니다. 상세 변경과 실제 실행의 한계는 [검증 기록](NAVIGATION_VALIDATION.md)을 참고합니다.
- 단위 테스트는 실제 Webots에서의 미탐지율·충돌률·완주율을 보장하지 않습니다.
