# 재방문 및 가구 근처 맴돌기 수정 기록

2026-09-30. 지도에 이미 나타난 공간을 모두 통행 금지하면 LiDAR가 먼저 본
통로로 전진할 수 없고 시작점으로 복귀할 수도 없다. 따라서 탐색 목적지 선택과
경유 가능 여부를 구분한다. 또한 LiDAR로 벽을 관측했다고 카메라로 사과까지
확인한 것은 아니다.

## 탐색 정책

- 목적지는 빈 공간과 미지 영역의 경계(frontier)에서 고른다.
- 도착한 목표 주변 0.35m는 같은 실행에서 다시 탐색 목적지로 선택하지 않는다.
- 0.75m 구역 단위로 진입 횟수를 기억한다. 0.4m 미만 위치 흔들림은 추가 진입으로 세지 않는다.
- frontier 점수는 `크기 / 거리^1.7 / (1 + 4 × 구역 진입 횟수)`다. 진입 횟수는 8에서 제한한다.
- 이미 지나간 구역은 후순위지만, 남은 미탐색 영역 접근이나 복귀 경로에서는 통과할 수 있다.
- 구역 맴돌기 탈출 시 실패 목표 기록을 지우지 않는다.
- 긴 경계의 대표점에 실패했어도 경계 전체를 버리지 않고, 실패·도착 지점을 제외한 다른 접근점을 고른다.

## 함께 확인한 원인과 수정

가구를 사람으로 판단한 후 동적 빔 제외 표시가 남아 지도에 가구가 반영되지 않는
문제를 수정했다. 정지 물체 판별 증거를 유지하며, 사람 추적 반경이 이미 점유된
벽을 동적 장애물로 덮어쓰지 못하게 했다. 실제 움직이는 장애물은 계속 회피한다.

가구 모서리 사이에서 매번 회전 방향을 바꾸지 않도록 짧은 회피 기동 동안 방향을
유지한다. 복구 전진과 탈출 방향 선택에는 빔 하나의 거리 대신 원형 차체가 이동할
때의 접촉 거리를 사용한다. 통과 가능한 틈은 유지하고 차체에 걸리는 모서리는 정지시킨다.

높이 등 기하 검사를 통과하지 못한 붉은 물체가 SEEK로 탐색을 계속 중단하지 못하게
했다. 지도 정합은 제자리 회전 명령 중 위치를 반복 이동시키지 않도록 제한했다.
이 제한은 전진 중 바퀴 미끄러짐이나 전역 위치 오차를 모두 해결하는 기능은 아니다.

붉은 배경이 작은 사과를 가리지 않도록 연결된 색상 후보를 개별 검사하며, 사과
뒤의 큰 가구 YOLO 박스가 겹친다는 이유만으로 후보를 거부하지 않도록 했다.
실제 실행의 탐지 거절 이유와 회피 상태는 live_view에 표시한다.

## 최신 코드 검증

실행 명령은 프로젝트 가상환경 Python을 사용한다.

| 확인 | 결과 |
| --- | --- |
| `python -m unittest discover -s tests -q` | 50/50 통과 |
| `python run_tests.py` | 15/15 통과 |
| `python -m compileall -q sar controllers tests` | 통과 |
| table, seed 7, 사람 없음 | 375.40초 완료, 충돌 0, 목표 1/1, 시작점 거리 0.2484m |
| table, seed 7, 사람 있음 | 371.25초 완료, 충돌 0, 목표 1/1, 시작점 거리 0.2500m |

오프라인 성공은 실제 위치의 목표 접근과 복귀 거리도 확인한다. 제어기의 DONE만으로
성공을 판정하지 않는다. 위 두 실행은 `sim_offline.run`과 `is_success`로 검사했다.
초기 중간 수정본에서는 좁은 틈에서 조기 탐색 종료 및 복귀 시간 초과가 발생했고,
이를 최종 통과 결과와 구분해 실행 로그를 `out/`에 보관했다.

## 실제 Webots 관측 범위

재방문 점수와 잘못된 SEEK 진입 방지를 적용한 중간 수정본의 독립 검증 실행
`c80e9e9a37e14a4f80744bf796d35b88`에서는 실제 위치가 시작 구역을 벗어났다.
첫 사과까지 최소 0.4401m, 두 번째 사과까지 최소 0.5222m로 접근했다.
시뮬레이션 1153초에는 방문 기록이 1/2였지만, 이후 두 번째 목표도 방문했다.
최종 1296.448초에 DONE, 방문 2/2, 실제 시작점 거리 0.1346m로 독립 검증을
통과했다. 종료 시 추정 위치와 실제 위치의 오차는 0.2836m였다. 이것은 미션
성공 확인이며, 접촉 센서로 전체 주행의 무충돌을 입증한 결과는 아니다.

이 실행에는 이후 추가한 원형 차체 통과 검사, 알려진 벽의 동적 분류 억제,
긴 frontier의 다른 접근점 선택 수정이 포함되지 않았다. 최신 코드는 일반 실행을
초기화하여 적용했다. 재방문 정책을 적용한 실제 아파트 완주 1회는 확인했지만,
마지막 추가 수정까지 포함한 일반 실행의 완주는 별도 확인이 필요하다.
전체 시나리오 sweep도 이 수정본으로 다시 통과했다고 주장하지 않는다.

독립 Supervisor는 평가 목적으로만 실제 위치를 기록하며, 항법 코드에 목표나 실제
위치를 전달하지 않는다. 위치 오차는 상태 데이터의 시뮬레이션 시각에 맞춰 비교한다.

## 화면과 적용

일반 실행은 `http://127.0.0.1:8765/live_view.html`, 독립 검증은
`http://127.0.0.1:8765/live_view.html?run=validation`에서 확인한다.
Python 변경은 Webots 시뮬레이션 초기화 후 적용된다. 브라우저 새로고침만으로는
실행 중인 컨트롤러 코드가 바뀌지 않는다.
